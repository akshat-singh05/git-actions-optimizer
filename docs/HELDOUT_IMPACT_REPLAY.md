# Counterfactual replay: skip jobs the graph says the diff cannot reach

Generated by `gha-optimizer replay-impact` from the database; every figure is computed from real job records (**MEASURED on history**), but the policy was not run: it assumes skipping a job changes no other job's outcome. Cluster bootstrap over runs (1000 resamples, seed 13). Method and limits: `gha_optimizer/replay.py` docstring.

Policy: skip a job when the graph at the run's commit says the diff does not reach it. *naive* skips every such job that ran; *dag_safe* only if every downstream (`needs`) job either did not run anyway or is also unreached; the *readable* variant also never skips a job (or lets one be skipped through `needs`) whose steps the graph cannot read - `make`, remote / composite actions, reusable-workflow calls - a guard added after the first replay showed prometheus's `make`-driven Go test job was the main source of misses. Unknown jobs are never skipped. Jobs the workflow already skipped by itself are not counted: this is the **additional** saving over the workflow as written. The rules were written after reading these workflows, so this is not a held-out test of the rules.
